### 最终取舍

- 保留 generation 合并：请求由 4 条降至 2 条，结构简化明确，目标面板多数场景有收益，维护成本低。
- 保留网关 latency 简化：旧轮 21/24、新轮 23/24 个目标场景中位耗时下降，20/24 个相同场景两轮均改善；新轮允许缓存的 12/12 组全部通过原 gate。两轮仅用于判断改善方向，不拼组，也不直接比较不同测量时点的绝对耗时。
- 保留 Token 简化，但不再为此追加专项优化工程：目标中位数改善方向较弱，两轮均改善为 14/24；输出 Token 的场景降幅中位数仅为 4.71%、节省 4.55ms。但它复用 latency 已需要的同一 helper，边际维护成本低，目前没有必要整类回退。XPU 输入 Token 的 1h/禁用缓存是唯一两轮均变慢的 Token 场景，约增加 4ms；其他窗口有收益，不据单一窗口增加表达式分叉或回退整个面板。
- 撤回 A3 新 revision，恢复原 catalog。新方案缺少与已有物化方案在相等历史覆盖下的收益证明；原式诊断不是该基线。将来若重启此项，应比较旧、新物化路径或实际 worker 资源收益，并计入历史命中损失和重新物化成本。

以上为本次候选的最终成本收益取舍，不把 39/60 组通过改写成性能门槛全面通过。独立探针与目标共享客户端 CPU 及服务资源，探针 P95 超标不能直接归因为 VictoriaMetrics 退化，也不能无证据认定全是噪声。

这是同一传输条件下新旧查询的对照，不用不同时刻的 HTTP 与 HTTP/2 数据推算协议升级收益。查询完成耗时与浏览器绘制时间分别记录。
