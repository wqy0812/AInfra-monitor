# 性能报告的服务缓存观测

实现状态：本地实现与合成验证完成，发布身份以发布记录为准。

性能报告复用实时监控已有的 DCU、A3、XPU Prefill 数据。消费者为 code-eval engine；Web 只读取平台保存的快照。统计包含推理后端的全部流量，不做逐请求归属，也不根据网关所在环境或性能模型描述选择指标。

## 来源关联

`monitoring/cache_sources.json` 登记推理业务端点与现有监控环境的关系，可通过 `CACHE_SOURCE_CONFIG` 指定外部只读配置。每条关联包含 `backend_url`、`environment`、`valid_from`、可选 `valid_until` 和证据说明 `evidence`。回环、私网、容器名称地址必须同时指定 `proxy_url`，避免不同代理的 `127.0.0.1` 被识别成同一后端。

匹配完整的规范化业务地址，保留路径和端口；不按 IP 猜指标端口，不读取模型名称，不自动追踪不透明的多级路由。每个时刻必须唯一匹配。关联中不保存凭据；旧报告引用的关联版本须保留，修改来源时增加有明确有效期的新记录，避免覆盖旧版本。

初始三个关联以只读运行状态与现有采集配置核对。历史有效期仅延伸到具有相同代理配置摘要的报告；原始核查证据保存在忽略的 `evidence/cache-reports-20261020/live-backends.json`。代理配置摘要覆盖后端配置，因此相同摘要可证明相同配置后端，但不证明过去进程 boot 一直连续，也不能证明不透明下游路由的选择。

## 内部接口

- `POST /api/monitoring/cache-sources/resolve` 接收 `backend_url`、`proxy_url`、`at`，返回 `resolved` 关联快照或带原因的 `unavailable`。快照包含来源版本、关联版本和统计口径。
- `POST /api/monitoring/cache-observations` 接收冻结的 `snapshot`、`start`、`end`、`offset_seconds` 和固定 `bucket_seconds=30`。单次最多六小时，时段必须在最近 30 天内，且结束至少过去 15 秒。接口核验已登记的来源、版本和有效期，不接受任意指标选择器。沿用 monitoring-api 的 IP 白名单。

查询不写 VM，不触发采集补算、模型请求或历史任务重放。接口一次返回 30 秒分桶的原生趋势、独立区间统计、有效时长及实例覆盖。请求失败会取消本次剩余 VM 查询，沿用已有查询并发限制。

## 统计口径

- DCU 的有效输入由 `device_hit + host_hit + storage_hit + input` 构成；A3 由原生按来源输入计数构成，并核对总输入、总缓存计数一致性。
- 汇总使用不重叠的 30 秒计数增量，再计算命中总量／有效输入总量；先逐序列检查基线、重置、完整采样和身份，再汇总。统计不累加重叠的一分钟窗口，不平均每点百分比。DP 组可累加 Token，物理实例覆盖不按 DP 组重复计数。
- XPU 使用代表 rank 的原生前缀比例，每个完整采样桶计算均值，再按桶有效时长加权，标注为原生比例时间平均。它不是 Token 加权值，也不能用于推断 CPU 层命中。
- 趋势使用实时监控现有原生记录，DCU／A3 仍为一分钟窗口，XPU 保持原生采样。每 30 秒取桶中心的趋势值；源缺样保持空白。
- 报告查询单独使用 `nocache=1` 保留实际开测时间的毫秒偏移，避免 VM 对 50 点以上查询的缓存时间轴对齐；普通看板查询保持原缓存方式。
- 汇总桶要求完整采样及新鲜边界观测，采集边界近似最多 10 秒。缺失、重置或身份变化的桶不跨越计算。部分实例有效时保留已知部分，覆盖信息同时返回；有效零命中保持零，无输入时比率为空。

验证入口：`bash scripts/test_local_vm.sh tests/test_cache_reports.py -q`，使用独立临时 VM，不调用真实模型。
