# 按全新监控建设目标重审原生记录规则

状态：**用户已批准 D1–D6（“按你的建议来”）。现行实现为 286 条 monitoring_native_* 规则；本页保留评审依据，发布结果单独记录。**

## 设计约定

2026-10-11 用户明确：生产尚未搭建，现有部署是测试环境。所有监控指标迁移允许提出口径变化，以简单、可解释的原生规则为目标；必须说明变化并由用户决定，不能默认永久复刻旧 Python 行为。此约定适用于已迁移和后续迁移的指标。

- 首选官方 vmalert + VM 原始指标计算，Perses 直接查询记录结果。
- 用清晰的窗口、单位、源标签和聚合维度定义指标；不按旧 JSON 路径设计新指标模型。
- 默认考虑固定 1m 统计窗口、5s 记录周期。看板查询 step 只控制显示采样，不改变统计窗口和有效性定义。
- 不以旧历史接续、每次启动自动补算、旧表达式匹配或原始查询回源作为新系统设计要求。原始历史不删除，新口径使用新指标名。
- 不能为了缩短表达式而重复计算 TP 副本、遗漏独立 DP、混淆请求/Token/Store 查询、合并互不等价的流式分区或相加分位数。这些是统计对象定义，不是可随意删除的兼容逻辑。
- 校验新定义是否正确，并以具体样本展示旧新差异；不再以逐点等价旧 Python 作为所有迁移的前置门槛。口径批准不等于免除源身份、查询正确性和看板验收。

| 编号 | 旧行为 | 建议新行为与影响 |
| --- | --- | --- |

| D4 直方图及跨字段验证 | 每桶数量/单调性/计数一致性、生命周期守卫；Python 分位落在 +Inf 返回空；缓存跨字段守恒失败整组空 | 原生直方图算法，不逐桶复刻验证；溢出可能返回最大有限桶边界。缓存保留单位、来源、分母>0及比例范围；跨字段守恒/桶质量改独立状态，不再默认遮蔽整组。源损坏时可能出现以前被拦截的数值，必须明确接受此取舍 |

## 源身份回顾：不能用统一 rank=0 替代正确聚合

经 SSH MCP 对 test4 VM 做只读标签核对，证据为 `evidence/native-standard-20261011/source-inventory.json`：

- DCU 请求与完成 Token counter 按 is_streaming=true/false 分区；XPU 使用未分区 tokenizer counter。候选分开选择，先按源 rate 再聚合，不把未分区总量与两分区再次累加。
- DCU Prefill 当前没有 dp_rank，8 个 TP/EP 是复制视图；候选缓存选 PP/TP/EP=0。
- DCU/XPU Decode 当前都有 8 个独立 DP，其 TP 编号包含 0–7；对 Decode 简单加 tp_rank=0 会遗漏独立计算。现行规则按 DP=TP、PP=0 保留全部 8 组，真实 VM 合成验证为 8 × 10 = 80 token/s；不能套用 Prefill 选择器。
- 改为配置明确的代表源，可以取消运行时动态选举；配置来源不存在应留空并报缺失，不自动切换另一个 rank 冒充相同统计对象。

## 已完成的候选和验证

`experiments/native_standard_rules.py` 生成 87 条独立原始查询规则，最长 790 字符：包含旧 18 项、A3 CPU、三环境吞吐/延迟和实例数、A3 前缀缓存、DCU/A3 分层缓存、XPU 原生命中率、两环境 Store 容量及 DCU Store 查询比率。新名字统一为 monitoring_next_*；运行入口不导入该模块。

验证使用本机独立 VM 1.151.0 和官方 vmalert 1.151.0，不向测试服务器写入候选记录。87 条表达式均在真实 VM 执行成功；12 类合成场景及官方 vmalert 写回后 46 条结果序列对照通过。见 `evidence/native-standard-20261011/probe.json`、`replay.log`。

| 合成场景 | 已验证的差异 |
| --- | --- |
| 最后 5 秒完成 120 次，此前无新增 | 旧最近两点为 24/s；固定 1m 为 2/s |

## 决定后的实施顺序

1. 按用户决定固定统计定义和源清单，补齐质量状态、独立 DP、动态 rank/device/segment 指标与必要的计数。
2. 用普通 metric 标签替代 Python JSON path，Perses 改为 VM 数据源，标题/说明标出 1m、统计对象和部分覆盖状态；不叠加两套长期兼容框架。
3. 验证候选源数据与新定义，再发布测试环境并检查受影响看板。生产使用同一简化方案从零部署。
4. code-eval 如继续使用 latest/history，API 改为读取记录结果并适配 JSON；请求画像等业务接口单独处理。移除被替代的 Python 数值预计算和旧加速读写适配。
5. 停用旧自动 replay 和不再使用的生成/代次协议，保留历史数据，记录切换边界。任何未在 D1–D6 披露的新口径变化再次提交用户决定。
